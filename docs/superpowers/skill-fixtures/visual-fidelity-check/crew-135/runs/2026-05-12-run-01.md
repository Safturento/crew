## High-severity findings

### F1: State badges pass `intensity="muted"` (no stroke) where Figma's agent-drawer uses `intensity="mid"` (1px state-colored stroke)

- **Kind:** caller
- **File(s):**
  - `packages/dashboard/src/components/AgentRow.tsx:67` (post-diff)
  - `packages/dashboard/src/components/AgentBody.tsx:62-72` (post-diff)
- **Code (AgentRow.tsx, post-diff):**
  ```tsx
  <Badge role="status" aria-label={meta.label} color={agent.state} intensity="muted" hasIcon>
    {meta.label}
  </Badge>
  ```
- **Figma reference:** Pill set node `272:120`. Variant `type=pill, color=running, intensity=muted` (`id 271:266`) has `strokes: []` — confirmed in `snapshot/composites/272-120.json:46`. The mid counterpart (e.g. `type=button-sm, color=running, intensity=mid` at `271:396`) emits `strokes: [{ hex: "#64748B", tokenAlias: "slate/500", weight: 1 }]`. The fixture description states the agent-drawer screen (`screens/1-756`) renders each state pill with the mid variant (visible 1px stroke). No screen-level JSON exists to mechanically verify which intensity the screen-level instance uses — see verification gaps.
- **Diff:**
  - Code (`intensity="muted"`) → `pillSurfaceClasses('running','muted')` returns `bg-slate-1050 text-slate-400` (no border class).
  - Figma intends the mid variant → should emit `bg-slate-1050 border border-slate-500 text-slate-400` (and equivalent per-state tokens).
- **Fix:** Change `intensity="muted"` to `intensity="mid"` in both `AgentRow.tsx:67` and `AgentBody.tsx:66`. Two lines total.

### F2: Clear attention button renders a bordered, filled pill where Figma intends a borderless, unfilled frame

- **Kind:** caller
- **File(s):** `packages/dashboard/src/components/TopNav.tsx:37-43` (post-diff)
- **Code (post-diff):**
  ```tsx
  <Button
    color="running"
    intensity="mid"
    size="xs"
    onClick={onClearAttention}
    disabled={attentionCount === 0}
    className="border-white/10 text-muted-foreground hover:bg-popover disabled:opacity-40"
  >
    Clear attention
    {attentionCount > 0 && (
      <Badge color="waiting" intensity="loud" className="font-semibold">
        {attentionCount}
      </Badge>
    )}
  </Button>
  ```
- **Figma reference:** Attention composite frame `243:120` in `snapshot/composites/243-120.json:18-21`: `resolvedStyles: { fills: [], strokes: [] }`. Its `designIntent` field: _"Unbordered horizontal frame (no fill, no stroke) containing a 'Clear attention' label + an instance of Pill type=pill/color=waiting/intensity=mid showing the count. Functionally a button but visually a composition — the closest Button mapping is color=running, intensity=ghost (no bg, no border, slate/400 text)."_
- **Diff:**
  - `intensity="mid"` emits `bg-slate-1050 border border-slate-500 text-slate-400`. The `className` override then repaints the border to `border-white/10` and text to `text-muted-foreground` (slate/400 effective), but the `bg-slate-1050` (#1C2538) remains — a visible dark fill where Figma has none. The `border-white/10` is also a visible (faint) border where Figma has none.
  - The className override is a hold-over from before the pill system existed.
- **Fix:** Change `intensity="mid"` → `intensity="ghost"`. Drop the `border-white/10 text-muted-foreground hover:bg-popover` portion of the className override; keep `disabled:opacity-40` if the disabled treatment is still wanted (Button's base `disabled:opacity-50` is close enough that even this is likely dispensable).

## Medium-severity findings

### F4: `pillSurfaceClasses('white', 'loud')` uses `bg-neutral-200` (#E5E5E5) where Figma uses `zinc/50` (#FAFAFA)

- **Kind:** structural (helper-level)
- **File(s):** `packages/dashboard/src/lib/pill-variants.ts:8-14`
- **Code:**
  ```ts
  const WHITE_CLASSES: StateClassTokens = {
    text: 'text-slate-950',
    bg: 'bg-neutral-200',
    border: 'border-slate-500',
    solidBg: 'bg-neutral-200',
    solidBorder: 'border-slate-500',
  };
  ```
- **Figma reference:** `snapshot/composites/272-120.json:107-116` — variant `type=button-sm, color=white, intensity=loud` (`id 271:438`): `fills: [{hex: "#FAFAFA", tokenAlias: "zinc/50"}]`, `textColor: {hex: "#09090B", tokenAlias: "zinc/950"}`.
- **Diff:**
  - Code (`white/loud`) → `pillSurfaceClasses('white','loud')` returns `bg-neutral-200 text-slate-950`. `neutral-200` is #E5E5E5 (Tailwind default).
  - Figma wants #FAFAFA (zinc/50). Delta of ~6.5 lightness units — visible as a slightly dim near-white where the design intends a brighter near-white.
  - Helper's tests in `pill-variants.test.ts` codify the wrong shade (`expect(result).toContain('bg-neutral-200')`), so the bug was pinned-in.
  - Surface area: New Run button in `TopNav.tsx` is the only known caller right now; helper still ships the wrong shade to any future `white/loud` call site.
- **Fix:** In `WHITE_CLASSES`, change both `bg: 'bg-neutral-200'` and `solidBg: 'bg-neutral-200'` to `'bg-zinc-50'`. Update the matching expectation in `pill-variants.test.ts` from `'bg-neutral-200'` to `'bg-zinc-50'`. Optional: align `text: 'text-slate-950'` (#020617) with Figma's `zinc/950` (#09090B); the hex delta is sub-perceptual so this is a low-priority follow-up rather than a required fix.

### F5: "View PR" and "Open as page" buttons use Unicode arrow glyph (`↗`) instead of an SVG icon

- **Kind:** caller (content-level mismatch)
- **File(s):**
  - `packages/dashboard/src/components/AgentRow.tsx:122-126` (post-diff, View PR action for pr_open agents)
  - `packages/dashboard/src/components/AgentBody.tsx:77-88` (post-diff, both View PR and Open-as-page)
- **Code (AgentRow.tsx, post-diff):**
  ```tsx
  <Button color="running" intensity="mid" size="xs" asChild>
    <a href={agent.prUrl ?? '#'} target="_blank" rel="noreferrer" onClick={stop}>
      View PR ↗
    </a>
  </Button>
  ```
- **Figma reference:** The Pill set has an `Icon` INSTANCE_SWAP property (`Icon#272:450` in `composites/272-120.json:10`) with a `Has Icon` BOOLEAN (`Has Icon#272:225`). The Button source's base classes (`[&_svg]:size-3` at the xs size in `button.tsx:21`) are already wired for SVG-as-child rendering — the system expects an actual SVG, not a Unicode codepoint.
- **Diff:**
  - Code uses Unicode U+2197 ("↗") embedded in the link text. Glyph metrics, stroke weight, and color follow the user-agent font fallback, not the design system.
  - Figma's pill renders the icon as a lucide SVG (e.g. `lucide/arrow-up-right`) whose stroke and color align with the pill's text token.
  - The Button's class engine sizes child SVGs to `size-3` (12px) at the xs size; a Unicode glyph gets no equivalent constraint.
- **Fix:** Replace the Unicode arrow with a lucide SVG, e.g. `import { ArrowUpRight } from 'lucide-react'` and render `<ArrowUpRight aria-hidden /> View PR` inside the anchor. Apply the same swap in `AgentBody.tsx` for both View PR and `↗ Open as page`. Three call sites total. Note: the Badge primitive does not yet support a separate icon slot beyond the `hasIcon` dot — for Button this works because SVG children render naturally; if a `leadingIcon` prop materializes later (followups already track this), migrate then.

### F6: `WorktreePathLink` "Copy" button still carries a stale `text-muted-foreground hover:text-foreground hover:bg-transparent` className override after migration to `intensity="ghost"`

- **Kind:** caller (stale override)
- **File:** `packages/dashboard/src/components/AgentBody.tsx:107-115` (post-diff)
- **Code (post-diff):**
  ```tsx

    intensity="ghost"
    size="xs"
    onClick={onCopy}
    aria-label="Copy worktree path"
    className="h-auto px-1 py-0 text-xs uppercase tracking-wide text-muted-foreground hover:text-foreground hover:bg-transparent"
  >
    {copied ? 'Copied' : 'Copy'}
  </Button>
  ```
- **Figma reference:** Not in this snapshot (no Figma node for the worktree-path chip captured). The judgment is based on the migration pattern: `color="running" intensity="ghost"` is meant to produce slate/400 text with no fill/stroke, which `text-muted-foreground` already resolves to. The `hover:text-foreground` override does add real behavior, so the className isn't entirely dead.
- **Diff:** `text-muted-foreground` is functionally equivalent to `text-slate-400` (the value `pillSurfaceClasses('running','ghost')` already emits). Layout overrides (`h-auto px-1 py-0 text-xs uppercase tracking-wide`) are real and intentional — the Copy button is a tiny inline affordance, not a standard xs Button.
- **Recommendation:** Flag in PR description as a "post-migration hygiene" note. The override does no harm visually; cleaning it up is a low-priority followup. Not blocking.

## Decision
