### Finding 5: "View PR" and "Open as page" buttons render a Unicode arrow (`↗`, U+2197) where Figma uses an `lucide/arrow-up-right` SVG

- **Kind:** caller (content shape)
- **File(s):**
  - `packages/dashboard/src/components/AgentRow.tsx:119-123` (View PR action)
  - `packages/dashboard/src/components/AgentBody.tsx:87-91` (View PR in drawer header)
  - `packages/dashboard/src/components/AgentBody.tsx:93-97` (Open as page — arrow is _prefixed_: `↗ Open as page`)
- **Code (AgentRow.tsx:119-123):**
  ```tsx
  <Button color="running" intensity="mid" size="xs" asChild>
    <a href={agent.prUrl ?? '#'} target="_blank" rel="noreferrer" onClick={stop}>
      View PR ↗
    </a>
  </Button>
  ```
- **Code (AgentBody.tsx:93-97):**
  ```tsx
  {
    mode === 'drawer' && (
      <Button color="running" intensity="mid" size="xs" asChild>
        <a href={`#/agent/${encodeURIComponent(detail.key)}/full`}>↗ Open as page</a>
      </Button>
    );
  }
  ```
- **Figma reference:** `snapshot/composites/272-120.json` defines a Pill-level `Icon` INSTANCE_SWAP property (`Icon#272:450`, defaultValue `199:106`) controlled by a `Has Icon#272:225` BOOLEAN. The agent drawer screen render `snapshot/screens/1-756.png` clearly shows the "Open as page" button rendering a thin geometric arrow glyph with explicit stroke weight — that's a `lucide/arrow-up-right` SVG, not a system-font Unicode character. The snapshot JSON doesn't carry per-instance `Icon` overrides for this row (REST API limitation, noted in `docs/followups.md`), but the Figma agent-drawer screen and the standard Pill leading-icon contract both point to `lucide/arrow-up-right` for an "open external / open as page" affordance. _Icon inferred from screen render + Pill `Has Icon` contract, not directly read from instance overrides._
- **Diff:** code emits a literal Unicode `↗` character that the browser renders via system font fallback (Symbola / Noto Sans Symbols on Linux, system emoji on macOS — frequently colored, frequently off-baseline). Stroke weight, color, and metrics drift from Figma's SVG icon, which inherits `currentColor` and has controlled 2px stroke.
- **Fix:** replace the Unicode character with the `ArrowUpRight` SVG from `lucide-react`. For example:
  ```tsx
  import { ArrowUpRight } from 'lucide-react';
  // …
  <Button color="running" intensity="mid" size="xs" asChild>
    <a href={agent.prUrl ?? '#'} target="_blank" rel="noreferrer" onClick={stop}>
      View PR <ArrowUpRight aria-hidden />
    </a>
  </Button>;
  ```
  Button's `[&_svg:not([class*='size-'])]:size-4` and the `size="xs"` override (`:size-3`) already handle SVG sizing. The "Open as page" variant should swap the leading position (`<ArrowUpRight /> Open as page`). The arrow icon is `lucide/arrow-up-right` specifically — not a generic "use an SVG".

### Finding 6: Badge `hasIcon` renders a CSS-only colored dot (`<span h-1.5 w-1.5 rounded-full bg-{color}>`) as a stand-in for what the Figma Pill defines as an `Icon` INSTANCE_SWAP

- **Kind:** caller / structural (Badge primitive choice)
- **File(s):** `packages/dashboard/src/components/ui/badge.tsx:43-49`
- **Code:**
  ```tsx
  {
    hasIcon && (
      <span
        data-testid="badge-dot"
        aria-hidden
        className={cn('inline-block h-1.5 w-1.5 rounded-full', dotClass(color))}
      />
    );
  }
  ```
- **Figma reference:** Pill set `Has Icon#272:225` is BOOLEAN, `Icon#272:450` is INSTANCE_SWAP with `defaultValue: "199:106"`. The state badges on the agents list (visible in `snapshot/screens/1-756.png`) render a small filled circle — visually a 6×6 colored dot, indistinguishable from the CSS approximation for this particular usage. The set-level default icon is _not_ a dot (it appears to be something else — likely `lucide/git-pull-request` per the previous calibration, but the JSON only gives us the node ID `199:106`).
- **Diff:** code primitive is `<span>` with `rounded-full bg-{color}`; Figma primitive is an SVG icon component instance. For the state-dot use case they render visibly equivalently. But:
  1. The Pill component never actually receives an explicit `lucide/circle` swap in the agent-screen overrides (the snapshot doesn't surface per-instance overrides — REST API limitation), so what icon Figma actually shows on the state badge is unverifiable from this snapshot alone.
  2. If Figma later changes the default `Icon` for `Has Icon=true` to a stroked-circle or filled-circle SVG, the CSS dot will silently drift.
- **Recommendation:** flag in PR description and file as a followup ("Badge `hasIcon` should accept an `<Icon>` slot or an `icon` prop, not paint a CSS span"). Not blocking for T1 — visually correct for the agent-row use case. Naming the right icon for the eventual fix: most likely a filled circle (e.g. `lucide/circle` with `fill="currentColor"`, or simply keep the CSS approximation and document that's intentional). Re-verify against a live Figma instance fetch when the next-tier change touches Badge.
- **Anti-loophole check:** the skill says icon CSS-approximations are flag-worthy (Step 4 sub-case). Flagging here as low rather than medium because (a) the rendered visuals match in this context and (b) the snapshot can't tell us what icon Figma is _actually_ using — it's a primitive-mismatch in theory but not a visible bug today. If the snapshot could confirm Figma uses a different glyph, this would escalate to medium.
