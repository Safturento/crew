# CREW-46 — Set up Bruno collection in crew daemon for API smoke runs

Jira: https://safturento.atlassian.net/browse/CREW-46

## Goal

Install `@usebruno/cli` at the repo root and ship a `bruno/` collection that
covers the daemon's two currently-implemented endpoints (`GET /health`,
`GET /api/projects`) so that crew-dispatched agents can run
`npm run bruno:smoke` against this repo's daemon as part of verification —
prerequisite for the value of CREW-43 (β) and CREW-44 (γ) to land in this
project.

## Relevant files

- `bruno/bruno.json` — collection metadata (the marker `bru run` looks for to
  pin the collection root).
- `bruno/.gitignore` — excludes `environments/` so per-worktree env files
  generated by CREW-42's writer never get committed.
- `bruno/endpoints/health/get.bru` — canonical reference for `GET /health`.
- `bruno/endpoints/projects/get-list.bru` — canonical reference for
  `GET /api/projects`, asserts response shape and the alphabetization
  promise the daemon makes.
- `bruno/flows/main-smoke.bru` — agent entry point referenced by
  `npm run bruno:smoke`. Today it duplicates `endpoints/projects/get-list.bru`
  because the daemon has no auth; once auth lands the flow will diverge to
  chain login → other endpoints.
- `package.json` — adds `bruno:smoke` script + `@usebruno/cli` devDep.
- `CLAUDE.md` — short addition describing the collection layout and pointing
  at the cross-project `bruno-collection-maintenance` skill.

## Decisions

- **One file in `flows/main-smoke.bru` plus one extra path in the npm script.**
  Bruno is one-request-per-file. The ticket spec called for a single
  `flows/main-smoke.bru` that "hits both endpoints in sequence". To keep the
  filename literal and still cover both endpoints, the npm script invokes
  `bru run` with two paths: the health endpoint card and the smoke flow.
- **`flows/main-smoke.bru` mirrors `endpoints/projects/get-list.bru` for now.**
  The daemon has no auth, so the flow has no chaining to do — it's just the
  most-meaningful endpoint with detailed asserts. The duplication is small
  and resolves naturally when CREW-33-era endpoints with auth land.
- **No login flow.** The daemon is local-only and unauthenticated. Per the
  ticket spec, no `[bruno_smoke.smoke_user]` will appear in
  `~/.config/crew/projects/crew.toml`.
- **Run via `cd bruno && bru run …`.** `@usebruno/cli` resolves the
  collection root from `process.cwd()` looking for `bruno.json`. Running
  from the repo root would fail. The npm script `cd`s into `bruno/` first.

## Out of scope

- Crew CLI changes — those are in CREW-41's child tickets (already merged in
  CREW-42/43/44).
- Adding `.bru` cards for endpoints that don't exist yet. New endpoints get
  their `.bru` as part of the ticket that adds them, per the
  `bruno-collection-maintenance` skill.

## Notes

- Default daemon port `7773` from `CREW_PORT` in
  `packages/daemon/src/config.ts`. If that default ever changes, update
  whatever local env file users hand-author (e.g. `bruno/environments/local.bru`).
- The TOML opt-in (`[bruno_smoke]` section in
  `~/.config/crew/projects/crew.toml`) is the user's responsibility once
  this lands; not part of this PR.
