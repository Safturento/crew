# design-sync notes — crew

Repo-specific gotchas for syncing the crew dashboard DS to claude.ai/design.

- `crew-dashboard` is a Vite **app**, not a built library — the bundle entry is the hand-authored `packages/dashboard/.design-sync.entry.tsx` (passed via `--entry`), which re-exports only the DS surface (23 components + compound subparts). Update it when scoping components in/out.
- `ui/form.tsx` is deliberately excluded: its react-hook-form `FormField` glue collides with the `FormField` composite (`src/components/FormField.tsx`), and a star-export of both would silently drop the name from the bundle. The composite is the DS component (matches the Figma `FormField`).
- `cssEntry` is `dist/assets/ds-entry.css`, produced by `.design-sync/prepare-css.mjs` (part of `buildCmd`): it copies the vite-hashed `index-<hash>.css` to a stable name AND rewrites root-absolute `url(/assets/…)` font URLs to relative — without the rewrite the font extractor silently skips every woff2 and validate fires `[FONT_DANGLING]` for all Fira Code/Hanken Grotesk faces. The compiled CSS carries all Tailwind v4 utilities used by the app plus the fontsource `@font-face` rules.
- npm workspaces hoist to the repo root: pass `--node-modules ./node_modules` (repo root), not `packages/dashboard/node_modules` (sparse, no react).
- **Dark theme in previews**: Tailwind v4 registers `--color-*` theme vars with `@property`, so their `var(--background)` references substitute AT `:root` — a `.dark` class on a descendant div never re-resolves them and everything renders light. The `DarkThemeRoot` provider (exported from the bundle entry, wired as `cfg.provider`) puts `dark` on `document.documentElement` via useLayoutEffect. Any design built with this DS needs the same: `dark` class on the document root (or wrap the app in `DarkThemeRoot`).
- Preview glue: inline styles only (arbitrary Tailwind utilities may be absent from the app-compiled CSS); previews import from `'crew-dashboard'`; overlay components render `open` with no-op `onOpenChange` + `cardMode: single` config overrides.
- **Preview CSS vocabulary**: the compiled CSS is the app's own Tailwind build — class strings copied from real call sites are safe (`font-mono text-xs`, `disabled:opacity-40`, `h-6 w-6`), but utilities the app never uses are absent (`w-8`, `w-10`, `size-5/6/8`, `h-px`, `text-emerald-400`…). Grep `ds-bundle/_ds_bundle.css` before using any utility in a preview; layout glue stays inline-style.
- **react-query context identity**: DrawerHeader/TopNav call react-query hooks against the copy bundled inside `_ds_bundle.js`; a preview importing `@tanstack/react-query` from node_modules gets a second module whose provider context never matches ("No QueryClient set"). The entry re-exports `QueryClient`/`QueryClientProvider` for this — previews must import them from `'crew-dashboard'`.
- **Preview harness quirks**: `.ds-cell`/`.ds-single` carry `transform: translateZ(0)`, so `position: fixed` backdrops are trapped — `createPortal(..., document.body)` instead (react-dom is shimmed to the page global). Radix portals escape the DarkThemeRoot div but still get dark tokens (the `dark` class lands on documentElement); the dialog scrim composites over the white harness body and reads mid-gray — cosmetic only. Capture pins the clock to 2024-05-15T12:00Z, so relative `started_at` fixtures give deterministic runtimes. The bundle's SSE client logs harmless `file:///api/events` errors.
- **Composition notes**: `AlertDialogAction`/`AlertDialogCancel` are intentionally unstyled — supply a `Button` via `asChild`. `DialogContent` ships its own close-X. Keep placeholder copy ≤~45 chars (truncates at max-w-lg). A complete valid `AgentDetail` fixture pair lives in `.design-sync/previews/DrawerHeader.tsx` — reuse for future data-bound previews.
- Component scope (2026-07-04, user-confirmed): `components/ui/` primitives + generic composites (Modal, AlertModal, ModalSelectionRow, FormField, Stepper, Drawer, DrawerHeader, TopNav, BrandMark). App-/data-bound components (AgentRow, Timeline, ProjectsTable, runner/, specific modals) deliberately out of scope.

## Re-sync risks

- **Stale compiled CSS**: `cssEntry` (`dist/assets/ds-entry.css`) is only as fresh as the last `buildCmd` run. If dashboard components gain new utility classes and the sync rebuilds without re-running the vite build, previews/designs silently lose those styles. Always run `buildCmd` when component source changed.
- **Previews borrow app class strings**: several previews use utilities that exist only because the app uses them (`disabled:opacity-40`, `font-mono text-xs`, the pill arbitrary selector). If the app drops a utility, the class vanishes from the compiled CSS and the preview degrades without a grade invalidation — eyeball contact sheets on re-sync.
- **Entry re-exports are structural**: `DarkThemeRoot` and the `QueryClient`/`QueryClientProvider` re-exports in `.design-sync.entry.tsx` are load-bearing (theme + DrawerHeader/TopNav previews). Removing them breaks previews at runtime, not compile time.
- **Preview fixtures aren't typechecked**: `.design-sync/previews/*.tsx` compile via esbuild (no tsc), so `AgentDetail`/`Route` fixture drift after schema changes surfaces as runtime blanks, not type errors. The canonical fixture pair lives in `previews/DrawerHeader.tsx`.
- **State union enumerated in three places**: the 10 `AgentState` values are hardcoded in the Tag/PillBase/Badge previews and named in `conventions.md`. Adding/removing a state means updating previews + conventions + re-validating the conventions vocabulary.
- **Toolchain assumptions**: render check ran against the repo's playwright 1.59.1 + cached chromium 1217; converter deps installed in `.ds-sync/` (gitignored — re-run the step-7 install on a fresh clone).
- **Overlay scrim cosmetic artifact**: dialog scrims composite over the white harness body and read mid-gray in cards — known, cosmetic, components themselves are fully dark-tokened.
